# College Educated Auto Engineer - notes for Claude Code

A mod for Railroader's built-in mod loader (Unity/Mono; built against game 0.6.x, played on 0.6.3 experimental (0.6.2 still supported: reach 0.6.3-only members by reflection); entry point `ModEntryPoint` in Main.cs, asset-pack Info.json, settings in Settings.xml). It improves the auto-engineer (AI) on the game's 0.6 rollout controller: smooth throttle, brake-tap and coast-band filters, no power into speed reductions, stall guard, gentle signal braking, speed-limit handling, water stop, shorter steam cutoff, optional realistic fuel use, starting resistance, direction-change pause, hill-start spool-up, diesel notch-1 starts, and with Wheelslip Prototype a slip guard, sanding and a car wheel lock guard. Namespace `CollegeEducatedAutoEngineer`, author Exp232. The old PID speed loop was removed in 0.6.0 and its code in this mod in 2.9.1: do not add PID-era patches back.

## Build (cloud sessions: BuildWatcher)
There is no `dotnet`, `mono` or `csc` in the cloud workspace, so the code is never compiled here. The build is done on the user's PC by BuildWatcher (repo `Exp232/BuildWatcher`, `Watch-Builds.ps1`, running as the scheduled task "Mod Build Watcher"):
1. Make the change in the clone, bump the version (below), commit locally.
2. Zip it: `git archive --format=zip --prefix=CollegeEducatedAutoEngineer/ -o /mnt/user-data/outputs/CollegeEducatedAutoEngineer-<ver>-source.zip HEAD ":(exclude).github" ":(exclude)dist"`. BuildWatcher rejects any path that is not a .cs, .md, Info.json, the .csproj or .gitignore, so keep .github/ and dist/ out.
3. Save the zip to the user's `C:\Users\exp23\Desktop\Projects\` with `device_commit_files` (`stagedPath` = the zip). The user's standing instruction: always save new builds there. If the bridge is down, say so and give the zip through `SendUserFile`.
4. BuildWatcher (checks every 5 s) sees a zip newer than the repo `Desktop\Projects\CollegeEducatedAutoEngineer`, and:
   - accepts only `.cs`, `.md`, `Info.json`, the `.csproj` and `.gitignore`, in `CollegeEducatedAutoEngineer/` or flat (not both), at most 5 MB unpacked; `Info.json` version must equal the file name's; otherwise it rejects it;
   - refuses to build if the `.csproj` changed beyond the version number ("needs review");
   - imports it as a commit `Import v<ver> source`, deleting repo files the zip leaves out (except `.gitignore` and `CLAUDE.md`), builds it, and on success pushes to `origin/main` and deploys to `Documents\Railroader\ModDev\CollegeEducatedAutoEngineer` (it waits while the game is running or the repo has uncommitted changes);
   - on a compile error it starts a headless Claude that may only edit existing `.cs` files; a fix is pushed as `Fix compile errors in v<ver> (automatic)`; if it can't, `main` stays put, the import goes to branch `incoming/v<ver>` and a GitHub issue lists the errors.
   - Its log is `watcher.log` (build errors included) and `state.json` (zips already handled, by hash) in the BuildWatcher folder. A zip is handled once; to retry the same version delete its entry or bump the version.
4a. Renamed from AutoEngineerBrakeFix in 1.0.0 (College Educated Auto Engineer), and the folder, assembly, identifier, namespaces, zip names and csproj were renamed in 1.0.1. BuildWatcher's config.json had `"Renames": ["AutoEngineerBrakeFix=CollegeEducatedAutoEngineer"]` for the move of the repo folder; remove that entry once it is done. Zips must be named `CollegeEducatedAutoEngineer-<ver>-source.zip` with the files in `CollegeEducatedAutoEngineer/` or flat.
5. Never push from the cloud clone: BuildWatcher pushes its own import commits and a push from here would collide. Do not mention unpushed commits to the user (they have said it is not needed). At the start of a session, `git fetch` and reset the clone to `origin/main` before editing, because local commits from an earlier session are not what BuildWatcher imported.
5a. Do not use version 1.0.3: BuildWatcher's csproj check replaces the new version number with the old one everywhere in the file, and the csproj has a package reference at `Version="1.0.3"` (Microsoft.NETFramework.ReferenceAssemblies), so a 1.0.3 zip is reported as "needs review". Skip it, or change the check to the `ReleaseVersion` line only.
6. A compile error is only known when the user pastes it, or from the Import/Fix commits and the GitHub issue. Be conservative: no local compiler, so grep every renamed member, check brace balance, and keep edits small. The Compiler Explorer tool (`mcp__Compiler_Explorer__compile`, `dotnet100csharpcoreclr`) compiles single files with stub types for the game and Unity; use it to check new logic in isolation, not the whole mod.

On a PC with the game: `dotnet build -c Release /p:DeployToGame=false` (game DLL path from `RailroaderDir` in the csproj, or pass `/p:RailroaderDir=...`). Do not deploy into the game's Mods folder unless asked. A compile-fix job: read the errors, fix them minimally without changing behaviour, repeat until clean, then show the diff.

## Conventions
- Harmony patches (0Harmony.dll ships with the mod). Every patch target and reflected member must be listed in `SelfCheck.cs` under the feature that needs it; private game types are taken as `object __0` and read by reflection (see `StartingResistance.cs`, `SignalPlanning.cs`, `BrakeTaps.cs`).
- The self-check switches a feature off in memory when a target is missing, and saving from the settings window then writes that false into `Settings.xml`. A feature whose patch is only installed when its setting is on must set `AlwaysPatch = true` and the patch must do nothing while the setting is off, so the window can switch it on. If a setting can be saved false by mistake, bump `Settings.CurrentSettingsVersion` and reset it in `Settings.Load`.
- Rollout controller path: `SpeedControlLoop_ApplyRolloutCommand_Patch` (BrakeTaps.cs) rewrites each `RolloutCommand` in this order: `WagonLock.EnsureIsolation` (once), `StallGuard.Filter` (returns early when latched), `DirectionPause.Filter` (returns early while it holds a train ordered the other way under 2 mph), `DirectionStop.Filter` (returns early after `WagonLock.Filter`: train brake only, independent bailed off, while a moving train has no order or target), `ReductionHold.Filter`, `BrakeTaps.Filter`, `CoastBand.Filter`, `RolloutThrottle.Filter` (smoothing), `SlipGuard.Filter` (throttle ceiling), `WagonLock.Filter` (train brake cap), then `CommandLog.Note`. Commands are relative (lever plus or minus 0.125 about once a second) and the controller reads the lever back, so a filter changes its next plan. `ThrottleGlider` eases the lever between ticks and runs the per-frame hooks (`StallGuard`, `TrainLights`, `HillStart`, `DirectionPause`, `SlipGuard`, `TrainPrep` `.Tick`). Game 0.6.3 leaves the speed loop for StopAndHold (full train and locomotive brake) whenever a moving train's command is zero or the other way (`IsMovingAgainstCommand`); `AutoEngineer_IsMovingAgainstCommand_Patch` (BrakeGuidance.cs) reports false while `BrakeGuidance.StopWithoutTarget` holds, so the direction stop stays in the rollout path. Below 1 mph the game's start-up loop sets the throttle itself from `CalculateThrottleForTargetVelocityStarting`; `AutoEngineer_StartingThrottle_Patch` (SlipGuard.cs) applies the diesel notch-1 start and the slip ceiling there.
- Manual driving: the game keeps a locomotive's `AutoEngineer` enabled while it is driven by hand (it only sets `Run` to false), so every per-frame hook runs then too. Anything that writes the controls must check `ae.Run` (the slip guard follows `SlipGuardManual`; the stall guard stands down).
- Shared reflection: `BrakeFix.TargetsOf(ae)` for the planner's targets, `BrakeFix.ReadControl/WriteControl` for the controls, `BrakeTaps.FAe/FTrainBrake/PApplied/FContextualField` for the rollout loop. Wheelslip Prototype is reached by reflection only (SlipSand, WagonLock); `WheelslipLink.Active` (SlipGuard.cs) tells loaded from running (0.9.8 refuses any game build but 0.6.2 build 26335745 and then patches nothing), so gate every use on it, and its brake-law patches are installed lazily (it loads after this mod).
- Target speeds and `MaxSpeedMph` are signed by direction of travel: compare magnitudes. `gradeUnderPct` negative = uphill in the direction of travel.
- Waypoint and Yard modes must keep the game's stopping accuracy; reduced accuracy only in Road mode.
- Keep defaults stable; the code defaults in `Settings.cs` are the user's own settings. When changing behaviour or a setting, bump the version in `Info.json`, `BUILDING.md` and the csproj together (all three; a version must be higher than the last import for BuildWatcher to take it) and add a `CHANGELOG.md` entry (newest first, under `# Changelog`). Update `README.md` for user-visible features. Removing a settings field is safe: XmlSerializer ignores unknown elements.
- Structs: `AutoEngineerPersistence` and `Orders` are structs, so assign a property through a local (`var p = new AutoEngineerPersistence(...); p.Orders = ...;`), never on a temporary (CS1612). The game calls the independent brake the locomotive brake (`LocomotiveBrake`); use that name in the settings window.
- Game physics notes: the game uses the Davis equation for resistance, journal bearings for everything, slack of about 0.04 m per coupler, per-car static friction via `IntegrationSet.ApplyBrakes`. `StartingResistance` adds a standing-start drag with an oil-film standing-time factor on top.
- In-game settings window: `SettingsUi.cs` (the game's `UIPanelBuilder` through `WindowManager.Shared.RegisterCustomWindow`, hotkey Ctrl+F8). `BuildPage` draws the page without a scroll view so the Mod Settings Hub can host it; `HubLink.cs` registers the page with the hub by reflection (copy of the hub's `HubLink.Template.cs`; do not list the hub in Info.json). A new setting that is read while the game runs should get a slider or toggle there, and `ResetDefaults` must reset it.

## Workflow
Logs (`ae_*.csv`, `signals_*.csv`, `fuel_summary_*.csv`) and decompiled game code come from the user. Log time = the file's start clock minus the first `t`; a new log opens each time the engineer is enabled. Useful columns: `cmdKind`, `cmdThr`, `outThr`, `cmdMod` (tap, which also marks the no-power-into-reductions hold; band; smooth), `cmdAgeS`, `nextTargetMph`, `nextTargetDistM`, `ctxTargetMph`, `gradeUnderPct`, `gravityKN`. This repo is the source of truth: if you fix something here, tell the user so they can pass the diff back. Project notes live in the Railroader Modding project's `claude/` docs.
